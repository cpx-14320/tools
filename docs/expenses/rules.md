# 記帳本（expenses）— 規則與執行規範

> 動這個工具之前先讀這份。這裡只寫**現在成立的結論 ＋ 一行為什麼**；
> 來龍去脈在 [history.md](history.md)（1400 行，含逐項稽核紀錄），待辦在 [status.md](status.md)。
> **色票、字級、間距在 [design.md](design.md)**——改樣式讀那份，這份不重複。
> 跨工具共通的規則在 [../README.md](../README.md)。

## 0. 這個工具要解決什麼

記下每一筆收支，月底回頭看錢花在哪、目標存了多少。資料量是五個工具裡最大的
（`lib/expenses` ＋ `components/expenses` ＋ 頁面約 25,700 行、13 個 Mongo collection），
所以**連動關係**是這個工具最容易壞的地方。

## 1. 架構

- **全部是 Server Component**：13 個頁面的資料都在 `page.tsx` 讀好、當 props 傳下去，
  **不要再用 `useEffect` 抓資料**。這是改過一輪的結果，不是現狀偶然如此。
- **lib 拆兩份**：`xxx.ts`（純函式，client 也能 import）與 `xxx.server.ts`（碰 Mongo／金鑰，
  只能從 `app/api/**` 或 Server Component 匯入）。
- **資料存 Mongo，以帳號為範圍**（`expenses.*` 13 個 collection）。
- **骨架（skeleton）已經全部移除**。只有搭乘車還在用骨架，改那邊的版面時才要同步改 skeleton。

## 2. 新增／刪除／編輯／還原：三條共用規則

這幾種資料互相牽連（分類→交易、帳戶→交易／轉帳／目標／固定收支），「刪了 A 又還原 B」的
組合會隨欄位變多而爆炸。所以規則寫死，加新欄位時回來對一次就好。完整對照表在
history.md 第八節。

1. **刪除一律先問**，文案依情境加碼。不分「乾淨的」或「還有紀錄在用的」——以前是刪得掉的
   不問、刪不掉的才問，剛好跟直覺相反。
2. **刪除是搬進垃圾桶，不是消失。** 垃圾桶不自動清空。**一次刪除＝一次還原**：主分類連同
   子分類、預算規則存成**同一個**垃圾桶項目，不會出現「分類回來了但預算沒回來」的半套狀態。
3. **刪除時盡量不去改動「指向它的人」**，否則從垃圾桶還原就接不回去了。唯一例外是**會繼續
   產生新壞資料**的情況（轉帳型固定收支的帳戶被刪 → 規則暫停）。

### `order`（排序編號）

| 動作 | 行為 |
| --- | --- |
| 新增 | `order` = 同層目前**最大值** ＋ 1（不是「有幾筆」——刪過之後筆數小於最大編號會撞號） |
| 刪除 | 不重新編號，序列留洞（0,1,2,**4**,5…）。重新編號會讓還原接不回原位 |
| 排序 | 整層重寫成 0,1,2,…，洞在這時候補平 |
| 還原 | 原位還空著 → 回原位；被佔走了 → 排到最後 |

系統分類（手續費、未分類）不參與排序，固定在最後。這兩個分類是**第一次用到才建**的
（第一次強制刪除分類時才有「未分類」、第一次記手續費才有「手續費」）。

## 3. 操作面的規範

| 項目 | 規則 |
| --- | --- |
| 釘住的工具列 | 一律走 `StickyToolbar`。右邊只有一兩顆按鈕的頁面**把標題也放進同一列**；有分頁切換的頁面維持標題在外面（不然釘住的部分會變兩列） |
| 選取工具列 | **固定一列**：左「全選 ・ 已選 N 項」，右「修改帳戶／修改分類／刪除」 |
| 退出選取模式 | 只有上面那顆「選取 → **取消**」。寫「完成」會被讀成「把剛剛選的送出去」 |
| 排序模式的「完成」 | **維持「完成」**：每按一次箭頭就已經存檔，離開時沒有東西可取消 |
| 待套用那一列 | 右邊是「**重選**／完成」。不叫「取消」——上面那顆退出選取的已經叫取消了 |
| 進行中的回饋 | **只用共用的處理中遮罩**（`useBusy()`），按鈕文字不換成「處理中…」。兩種回饋並存會讓人懷疑沒變字的那顆沒按到 |
| 系統分類 | 選取模式下兩個都不能勾、整張卡淡化。它們刪不掉，勾得起來卻刪不掉等於讓人白勾一輪 |
| 卡片裡的工具列 | 用 `StickyToolbar` 的 `inCard` 版本，而且那張卡要拿掉 `overflow-hidden`——它會讓裡面的 `position: sticky` 失效 |
| 提示文案 | 「N 筆已改為「X」」，不是「已改好 N 筆，改成 X」 |

## 4. 用詞（統一過的，不要再改回去）

| 一律叫 | 不要叫 |
| --- | --- |
| 收支分類 | 消費分類 |
| 子項目 | 項目、子分類 |
| 帳戶總表 | 資產總表 |
| 還原 | 復原 |
| 購買／買下 | 儲存（商店的確認鈕） |

刪除確認的口吻統一成「**將永久刪除…會保留…**」。還沒統一的在 status.md。

## 5. 主視覺的角色對話（OS 泡泡）

程式在 `lib/expenses/pet-os.ts`（判斷＋句子池）與 `components/expenses/pet-os-bubble.tsx`。

- **不是報表，是替使用者講出他心裡那句話。** 句子刻意不帶數字——數字在底下的卡片已經寫得
  很清楚。判斷只決定抽哪一池句子。
- 時間窗是**近 7 日 vs 前 7 日**（消費習慣以週為單位循環）。七種狀態與門檻全部集中在
  `OS_THRESHOLDS`，調整不用翻程式。
- **每個比例條件都要再加一個絕對金額門檻**：從 80 變 200 也是 2.5 倍，但那不值得講話。
- **同時成立的狀態把句子池合起來抽，不排優先序**——排在後面的句子會永遠不出現。例外是
  `saving`（花得少跟花得多不可能同時成立）。
- **seed 從伺服器傳下來**（`newOsSeed()`）：首頁是 Server Component，兩邊各自 `Math.random()`
  會 hydration mismatch 並閃一下。
- 顯示：一句停 15 秒，淡出 400ms → 換字 → 淡入；只有一句時不啟動計時器；用 `setTimeout`
  重排不用 `setInterval`（切到背景再回來會一次補跑好幾輪）；框置中但**字靠左**；
  `max-w-[260px]`（一句最多兩行）。

## 6. 怎麼驗

```
npm run check:expenses
```

`scripts/expenses-feature-check.mts` 直接呼叫 `lib/expenses/*.server.ts`（跟 API route 背後
同一份邏輯），不透過 HTTP、不用開 dev server。它會在 `users` 建一個**真的**測試帳號
（`qa-expenses-check-<時間戳記>`，走 `createUser` 同一套邏輯），模擬剛註冊的新帳號跑過 16 段：

預設資料／分類／帳戶類型與帳戶／交易（含拆明細）／轉帳與手續費／預算／存錢目標／固定收支／
垃圾桶（撞名改名、永久刪除、清空）／交易批次／CSV 匯出匯入／AI 待確認草稿／養成（簽到、
商店、餵食、服裝 `minLevel`）／偏好設定／範例資料提示／預算生效月份。

跑完不管成功失敗都在 `finally` 把測試帳號與它的資料清乾淨。報告寫到
`scripts/.feature-check-report.txt`（已在 `.gitignore`）。

**這支腳本不測 UI。** 按鈕有沒有接對、版面好不好用、文案講不講得清楚都測不到——那些記在
status.md，要抓新問題還是得真的開瀏覽器走一遍。

另外三支是一次性維護腳本，不是測試：`expenses-account-inventory.mts`、
`expenses-dedupe-presets.mts`、`expenses-repack-order.mts`。

## 7. 踩過的坑

- **金鑰不要用固定的 localStorage 鍵**：OpenAI API Key 原本存 `cpx-tools:expenses:openai-key`
  且不綁帳號，同一台瀏覽器換帳號登入會直接繼承前一個帳號的金鑰。
- **刪帳號要連所有工具的資料一起刪**（`lib/admin.ts`）：原本只清 `transit.*`，記帳本 13 個
  collection 整份留著變孤兒資料，而確認視窗卻寫「各工具底下的資料也會一併刪除」。
- **前端 `res.json()` 失敗不要默默 catch**：dev server 的 compile worker 掛掉時 API 回的是
  500 的 HTML，畫面悄悄還原，看起來像「按了沒反應」。所有失敗都要在畫面上跳提示。
- **Tailwind v4 的 preflight 拿掉了 `cursor: pointer`**：原生 `<button>` 的游標是箭頭，整個
  App 的按鈕滑過去都不像可以點。`globals.css` 補一條 base 規則一次蓋掉。
- **養成的服裝有 `minLevel`**：買得到但等級沒到就是換不上（刻意的設計，說明寫著「衣服可以
  先收進背包，解鎖後再換」）。寫測試時別把這個當 bug。
