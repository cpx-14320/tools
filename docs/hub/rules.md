# 入口與帳號（hub）— 規則與執行規範

> 2026-11-27 建立。這一層以前沒有獨立文件，規則散在
> `components/site-shell.tsx`、`components/ui.tsx`、`app/hub-view.tsx` 的檔頭註解裡。
> 範圍是「不屬於任何單一工具」的那些頁：入口頁、登入、註冊、管理後台、無權限畫面。
> **色票、按鈕、版面在 [design.md](design.md)**——改樣式讀那份，這份不重複。
> 跨工具共通的規則在 [../README.md](../README.md)。

## 0. 這一層要解決什麼

這個站是一個**工具包**：一個帳號、底下幾個各自獨立的小工具。hub 這一層回答三件事——
我是誰、我能用哪些工具、怎麼進去。

## 1. 一種版型，不管螢幕多寬

入口頁、登入、註冊、管理後台、無權限畫面共用 `SiteShell`：**不管幾吋都是同一張置中的
430px App 卡片**。

以前這裡是「手機＝App 外框、lg 以上＝1120px 網頁版型」兩套 responsive 版型，問題是點進
記帳本、搭乘車之後又變回 430px 手機框（兩個工具都只有手機版），在桌機上看起來像從一個網站
跳到另一個 App。現在整個站從登入到工具內部是同一個東西，寬螢幕就是「桌面上放著一支手機」。

卡片的尺寸／圓角／白邊／陰影／漸層底**刻意跟 `ExpensesMobileShell` 完全一致**
（`h-dvh`、`sm:h-[850px]`、`max-w-[430px]`、`sm:border-[6px]`、同一條三段漸層），
所以從登入頁按進記帳本時外框不會跳動。兩邊各自維護一份樣式字串，但**數字要對齊**。

`header` 不在捲動區裡（`shrink-0` 的 flex 子項，`main` 才是 `overflow-y-auto`），
所以內容再長，左上角的返回鍵永遠看得到——管理後台的使用者清單再長也不會變成死路。
返回鍵的標籤要寫**目的地的名字**，不要只放一個「‹」。

## 2. 圖示一律用 Font Awesome，不用表情符號

表情符號的長相由作業系統字型決定，大小與基線對不準旁邊的文字，跟工具自己的插畫
（`public/hub/*.png`）也不是同一種畫風。所以這幾頁走 `components/ui.tsx` 的 `FaIcon`。

`lib/tools-registry.ts` 的 `icon`（emoji）只是沒有插畫時的墊底值，有 `iconImage` 就用圖、
沒圖但想指定線條圖示就填 `faIcon`。

記帳本、搭乘車各有一份同名的 `FaIcon`，**三邊刻意各自維護**——那是模組邊界，不要收斂成一份。

## 3. 載入中不要顯示猜的狀態

工具清單是靜態資料（`TOOLS_REGISTRY`）、一定畫得出來，但「能不能點」要等
`/api/auth/me` 回來才知道。先畫一個猜的狀態再改，使用者會看到「需要權限」閃一下變成可以點。

所以 `loading` 時帳號卡那一塊**整個不畫**（它的兩種長相——帳號卡／登入邀請——差異太大，
先畫錯的再換等於整頁跳一次），而下面的工具清單高度固定，版面不會上下亂跳。

## 4. 帳號與權限

- Session 放 cookie（`cpx_session`），`getSessionUser()` 用 React `cache` 包起來，
  同一次請求只查一次。
- **工具權限是逐一授予的**（`UserDoc.tools`）。新工具預設不開，要去 `/admin` 勾。
  API route 一律用 `requireTool(toolId)` 把關，不要在頁面層自己判斷。
- 密碼走 bcrypt（`hashPassword` / `verifyPassword`）。測試腳本建帳號時要走同一套
  （`createUser`），不要自己塞一個明碼進去。
- **新增工具只要改兩個地方**：`lib/tools-registry.ts`（唯一來源，`lib/mongodb.ts` 會自動把它
  upsert 進 `toolsRegistry` 集合）與該工具自己的 `app/tools/<id>/layout.tsx` 權限檢查。
  完整清單見 [../README.md](../README.md) 的「新增一個小工具時，要一起做的事」。

## 5. 刪帳號要連所有工具的資料一起刪

`lib/admin.ts` 的 `deleteUserCascade`。這條單獨列出來是因為踩過：原本只清 `transit.*`，
記帳本 13 個 collection 整份留著變孤兒資料，而確認視窗卻寫「各工具底下的資料也會一併刪除」
——**畫面承諾了什麼，程式就要真的做到**。加新工具時這個函式要跟著加。

管理後台的刪除確認用**批次選取 ＋ 從底部升起的確認卡**，不用 `window.confirm`。

## 6. 怎麼驗

這一層沒有專屬腳本。`check:expenses` 會順便驗到 `createUser` 與權限預設值（它真的建一個
測試帳號），但入口頁、登入、註冊、後台的畫面都要人工走一遍：

```
npx tsc --noEmit
npx eslint app components lib
```

人工要走的路徑：未登入看入口頁（工具列得出來、標著「請先登入」）→ 註冊 → 進一個有權限的
工具 → 進一個沒權限的工具（要看到無權限畫面不是 500）→ 後台改權限 → 後台刪帳號。
